# Patient Privacy Smart Contracts

This project implements a **patient privacy and access management system** using smart contracts deployed on the Polygon Mumbai testnet. It lets patients control who can view their medical records. The actual records are encrypted off‑chain (e.g. stored in IPFS or a secure database), while the blockchain holds only metadata, ownership, and access permissions.

## Workflow Overview
1. Patients upload an encrypted medical record off‑chain and call `createRecord(hash)` on the smart contract. The hash is stored on‑chain.
2. Doctors request access; the request is logged off‑chain and/or reflected in your web app UI.
3. Patients grant or revoke access with `grantAccess`/`revokeAccess` functions. Only the record owner may perform these actions.
4. When a doctor attempts to view a record, the front‑end checks `hasAccess` on‑chain before retrieving and decrypting the off‑chain file.
5. All actions (creation, grant, revoke) emit events and are immutable.

## Local Development
1. Copy `.env.example` to `.env` and fill in your **Alchemy/Infura Mumbai URL** and **private key**.
2. Install dependencies: `npm install`
3. Compile contracts: `npm run compile`
4. Run the test suite: `npm run test`
5. Deploy to Mumbai: `npm run deploy:mumbai`

### Start the application
The application has a Django API and a Vite frontend. Start them in separate terminals from the repository root:

```powershell
cd backend
python manage.py migrate
python manage.py runserver 127.0.0.1:8000
```

```powershell
cd frontend
npm install
npm start
```

Open `http://localhost:8080` in a browser. The frontend uses `http://127.0.0.1:8000/api/v1` for API requests by default. Set `VITE_API_BASE_URL` in `frontend/.env` to override it.

## Front-end (React)
The Vite/TypeScript React application is under `frontend`. It provides patient and doctor dashboards, MetaMask authentication, record management, and access management.

### Running the front‑end
1. **Install dependencies**
   ```bash
   cd frontend
   npm install
   ```
2. **Set contract address**
   - Set any frontend environment values required by the current deployment in `frontend/.env`.
3. **Start development server**
   ```bash
   npm start
   ```
4. Use MetaMask (Mumbai network) to interact with the DApp through the forms. Keep the backend running at the same time.

### Front‑end details
- `frontend/src/App.tsx` defines the routes and dashboard access rules.
- `frontend/src/context/WalletContext.tsx` manages MetaMask connection, account switching, and message signing.
- `frontend/src/context/AuthContext.tsx` stores the authenticated user and role.
- `frontend/src/services/api.ts` requests a nonce, signs the authentication message, and calls the Django API.

## Authentication flow
1. Select **Switch MetaMask account** when creating an account or signing in. MetaMask opens its account chooser, and account changes are synchronized with the app.
2. During registration, enter a name, select `Patient` or `Doctor`, choose the wallet, and approve the message signature.
3. The backend creates or updates the wallet profile with the selected role and returns JWT access and refresh tokens.
4. During login, the wallet must already have a registered profile. An unregistered wallet is sent to the registration page instead of being silently created as a patient.
5. The returned role controls the dashboard route: `/patient/dashboard` or `/doctor/dashboard`.
6. The backend nonce is single-use and expires after ten minutes. Its signature verifier accepts the URL-safe characters generated by the nonce generator.

### Authentication troubleshooting
- `Failed to fetch`: make sure `python manage.py runserver 127.0.0.1:8000` is running and that the frontend API URL is correct.
- `Invalid signature`: reject any open MetaMask signature request, switch to the intended account, and start the login or registration flow again.
- A wallet that is not registered cannot log in; use the registration link to create its patient or doctor profile first.
